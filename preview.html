What is this?A library management SaaS, in plain language.

A library management system is the software a library lives inside — staff use it dozens of times a day, patrons feel it every time they borrow a book. Library Cloud is a complete, modern one that anyone can deploy and anyone can sell.

🏛️

For a library

A modern catalog, circulation desk, hold queues, fine math and member records — with a branded public website where patrons self-serve. A fraction of legacy ILS prices, nothing to install.

🚀

For an entrepreneur

Multi-tenancy, plans, signature-verified billing webhooks, white-label branding and an operator console — the unglamorous machinery of a SaaS, already built and tested.

🧑‍💻

For a developer

A non-trivial reference codebase: NestJS 12, Next.js 16, Postgres 18 row-level security, Playwright, 162 tests in total. MIT — fork it, extend it, ship it.

Prove itSix questions. Immediate answers.

A quick check — with explanations after every answer. All of it is somewhere in this page or the README.

1. What is the difference between a title and a copy?

Right: a title is the work; copies are the physical items. Holds, loans and branches care about copies — search and metadata care about titles.

2. A patron joins the waitlist for a book whose copies are all out. What makes it “ready”?

Right: hold promotion is automatic on return — that is the single most loved feature of a circulation system, and it is one of the backend’s tested behaviors.

3. Where is multi-tenant isolation enforced in Library Cloud?

Right: the three-lock model — RLS with FORCE + non-owner role + transaction-scoped SET LOCAL app.current_tenant. Cross-tenant reads are impossible even if application code has a bug, and isolation tests exist to try to break it.

4. What does a fine cap do?

Right: the per-day rate multiplies by overdue days up to a maximum. Library Cloud ships with $0.25/day and a $50 cap, and both are per-library settings.

5. The staff and patron sign-ins use different token scopes. Why does it matter?

Right: three audiences — staff, patron, platform — with separate storage and guarded endpoints. A token used in the wrong audience is rejected server-side.

6. You want to sell Library Cloud as a subscription business. Which pieces are already built?

Right: the whole unbundled toolkit — with a local stub provider for self-hosting and a Paddle integration for selling. The playbook in docs/BUSINESS.md covers pricing and the first ten customers.

Under the hoodBoring technology, serious guarantees.

One deployment serves every library. Postgres keeps every tenant sealed; Redis remembers rate limits; Caddy handles certificates for every custom domain.

Redis 8rate limits & cache — losing it degrades, it never breaks the library

The isolation contract in one line: every request runs inside a transaction with SET LOCAL app.current_tenant, every tenant table forces row-level security, and the app connects as a role that cannot bypass it. The tests exist to prove it.
